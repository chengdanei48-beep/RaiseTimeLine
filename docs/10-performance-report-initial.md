# 性能テスト初回レポート(2026-10-29)

[性能テスト基盤](09-performance-testing.md)(#76)の初回実行結果。実測値は `perf/results/<日時>/` の JSON(Git 管理外)から転記した。

## 1. 結論

- 学習規模(投稿 5,000 件)とその 10 倍(50,000 件)のどちらでも、**すべての合格基準を満たした**(k6 の閾値違反なし、ブラウザの閾値違反なし)。
- API は 15 VU・5 分の閲覧中心の負荷で、timeline の p95 が **約 13〜14ms**(基準 500ms)。失敗 0%。
- 件数が 10 倍(5,000 → 50,000)になっても p95 は約 1ms しか増えなかった(カーソル方式と部分インデックスが効いている)。
- 画面は、ログインからタイムライン表示まで **約 240〜260ms**(基準 1 秒)。CPU 4x・Fast 4G 相当でも約 930ms。
- ただし負荷は軽く(15 VU、ユーザー 50 人)、**余裕の大きさは確認できたが限界は未確認**。`stress` / `soak` は未実施(7 章)。

## 2. 実行条件

| 項目 | 5,000 件 | 50,000 件 |
|---|---|---|
| 実行 | `-Target combined`(`perf/results/20261029-133817`) | `-Target all -Rows 50000`(`perf/results/20261029-134352`) |
| データ | users 50 / posts 5,000 / follows 500 / likes 12,498 / comments 7,500 | users 50 / posts 50,000(他は比例して増加) |
| API 負荷 | k6 `read-mix` 15 VU(30s 増 → 4m 維持 → 30s 減)。ブラウザ計測の**背景負荷**として同時実行 | 同じシナリオを**単独で**実行。その後ブラウザを負荷なしで計測 |
| 環境 | ローカル(Windows 11 / Docker Desktop)。Spring Boot(perf プロファイル、Hikari 最大 10)・PostgreSQL 17・Vite preview(本番ビルド) | 同左 |

> **注意**: 5,000 件のブラウザ計測は背景負荷つき、50,000 件は負荷なしで測っており、**ブラウザの値を件数だけの差として厳密には比較できない**。k6 側は両方とも read-mix 15 VU で比較できる。

## 5. 参考: 動作確認(smoke)

1 VU で主要 16 リクエスト(ログイン、タイムライン 2 種、投稿詳細、コメント、プロフィール、ユーザー投稿、検索、me、いいね、フォロー、投稿・コメント作成、投稿削除)がすべて 2xx。平均 33〜49ms、p95 111〜164ms(初回のウォームアップ込みの 1 回きりの値)。

## 6. 所見

1. **現状の設計で、今回の規模には十分な余裕がある**。API は基準の 1/35 程度、画面は基準の 1/4 程度。
2. **件数依存は小さい**。5,000 → 50,000 で timeline の p95 は 13.0 → 13.8 ms(`all`)。keyset ページングと `idx_posts_timeline`(部分インデックス)が効いている。いいね数・コメント数の `COUNT(*) GROUP BY` も、1 ページ 20 件の範囲では問題になっていない。
3. **CPU・回線が弱い端末でも許容範囲**。4x 低速 CPU + Fast 4G でも、初期表示 931 ms、LCP 1,268 ms。ロングタスクはスクロール中に 5 回出たが、TBT は Lighthouse で 0。
4. 余裕が大きく、**今の条件ではボトルネックを特定できていない**。

## 7. 限界と未実施

- **負荷が軽い**: 15 VU・ユーザー 50 人・投稿の偏り無し。`stress`(〜100 VU)・`soak`(30 分)・`write-mix`・`login`(BCrypt)シナリオは未実行(仕組みはある)。接続プール(最大 10)の枯渇や、書き込み混在時の挙動は未確認。
- **EXPLAIN 調査は未実施**: 計画していた `EXPLAIN (ANALYZE, BUFFERS)` による実行計画の確認は、今回行っていない。データ量をさらに増やす前に実施する。
- **エンドポイント別の値が不足**: k6 の `--summary-export` は閾値を付けた指標しか出さない。投稿詳細・プロフィール・検索などの内訳は、閾値の追加か `--out json` での出力が必要。
- **ブラウザ計測の API 応答時間**: `measure.mjs` の `slowestApi`(遅い API の上位)が空で出力されている(取得方法の不具合)。画面別の API 内訳は今回の結果にはない。
- **LCP の取り方**: 上記 4.2 のとおり累積値。画面ごとの LCP が必要なら、画面ごとにページを読み直して測る必要がある。
- **環境差**: ローカルの値は、変更前後の比較用。AWS 上の値とは一致しない。
- **画像**: 画像添付(presign 経由)は対象外。画像つき投稿の表示は未計測。
